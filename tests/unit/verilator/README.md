## Краткое описание проблемы:

**"Гонка данных Verilator-C++: изменение входов одновременно с тактовым фронтом приводит к недетерминированному поведению регистров"**

## Суть проблемы:
- В реальном железе: данные должны быть стабильны **до** фронта такта (setup time)
- В Verilator: `eval()` вычисляет все комбинационно, поэтому изменение входов **во время** фронта такта создает артефакты симуляции

## Методы решения (памятка):

1. **Жесткое правило**: Все изменения данных - **только при clk=0**
2. **Последовательность**: 
   - Установить данные
   - `eval()` + `dump()` 
   - Поднять clk=1
   - `eval()` + `dump()` (фронт такта)
   - Опустить clk=0
   - `eval()` + `dump()`
3. **Разделение во времени**: Между изменением данных и фронтом такта должен быть минимум один `eval()`

## Код-памятка:
```c
// ПРАВИЛЬНО:
top->data = value;    // данные при clk=0
top->eval();          // стабилизировать
top->clk = 1;         // фронт такта
top->eval();          // захват данных

// НЕПРАВИЛЬНО:
top->clk = 1;         // фронт такта
top->data = value;    // данные меняются слишком поздно
top->eval();          // гонка!
```

**Verilator требует строгой временной дисциплины - данные должны "успеть установиться" до фронта такта!**

## памятка для WISHBONE:

```c
// WISHBONE: сигналы меняются сразу после переднего фронта!
// Фаза 1: Фронт такта - захват данных
top->clk = 1;         // POSEDGE - регистры захватывают значения
top->eval();
if (trace) trace->dump(sim_time);
sim_time += 1;

// Фаза 2: Чтение выходов и установка новых значений
// Здесь читаем ack, err, rty, dat_r
uint32_t read_data = top->dat_r;
bool ack_received = top->ack;

// Устанавливаем новые значения для СЛЕДУЮЩЕГО такта
top->cyc = next_cyc;    // Меняем сразу после фронта!
top->stb = next_stb;
top->we = next_we; 
top->adr = next_adr;
top->dat_w = next_data;
top->eval();
if (trace) trace->dump(sim_time);
sim_time += 4;        // дельта + 5

// Фаза 3: Сброс такта
top->clk = 0;
top->eval();
if (trace) trace->dump(sim_time);
sim_time += 5;        // дельта + 10
```

## Ключевые особенности WISHBONE:
1. **Сигналы меняются сразу после переднего фронта такта**
2. **Установка новых значений происходит в той же фазе, что и чтение результатов**
3. **Временные параметры определяются стандартом WISHBONE**
4. **Это отличается от обычных регистров!**
