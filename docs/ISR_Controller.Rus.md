# Спецификация: Контроллер Прерываний (IRQ Controller)

**Назначение:** Фиксация событий, генерация запроса `INT` процессору, предоставление информации о причине прерывания коду супервизора.

**Регистр статуса (IRQ Status Register) - Read Only (порт: `0xXX`)**
Биты регистра устанавливаются аппаратно по событию и сбрасываются программно записью в порт ACK.
Совершенно верно! Вы правы, устройств больше, и подход с иерархией — это единственно верный путь для сохранения системы простой, расширяемой и KISS-совместимой.

Ваше предложение — сделать центральный контроллер "сигнальным", а детализацию оставлять на откуп самим устройствам — это классическая и правильная архитектура.

### Уточнённая спецификация с иерархией

Центральный контроллер отвечает на вопрос **"Кто вообще прервал?"**, а конкретное устройство отвечает на вопрос **"И что именно у тебя случилось?"**.

### Спецификация: Центральный Контроллер Прерываний (Master PIC)

**Назначение:** Первичная диспетчеризация. Фиксация запросов от основных групп устройств, генерация `INT` для CPU.

**Регистр статуса (IRQ Status Register) - Read Only**

| Бит | Название        | Описание (Группа устройств)                                                                                           |
|:----|:----------------|:----------------------------------------------------------------------------------------------------------------------|
| 7   | **EXT_SLOT**    | **Ошибка внешнего слота.** Логика "таймаута" для всех слотов. Достаточно одного бита на все слоты (KISS).             |
| 6   | **BUS_CRASH**   | **Краш шины.** Аппаратный контроль целостности (запись в ROM, чтение из "дыр").                                       |
| 5   | **SUPER_BTN**   | **Кнопка "Supervisor".** Аварийный вызов.                                                                             |
| 4   | **LEGACY**      | **Группа legacy-устройств.** Общий сигнал от старой периферии (объединяет несколько источников через логическое ИЛИ). |
| 3   | **AUDIO**       | **Группа аудио.** Общий сигнал от звукового контроллера (таймер, DMA, ошибка).                                        |
| 2   | **GPU**         | **Графический контроллер.** VBlank, HBlank, завершение рендера и т.д.                                                 |
| 1   | **DMA**         | **Группа коммуникаций.** Последовательный порт (UART), сеть.                                                          |
| 0   | **STORAGE/COM** | **Группа контроллеров хранения.** FDC (флоппи), IDE/SD-контроллер.                                                    |

**Пояснение по группам (Иерархия):**

*   **Бит LEGACY:** Объединяет сигналы от старого таймера (CTC), VDP (ради совместимости) и UART. Это нужно, чтобы не занимать отдельные биты под каждое устаревшее устройство. Внутри ISR для `LEGACY` код будет опрашивать эти устройства *последовательно* (это допустимо, так как это legacy).
*   **Бит AUDIO:** Звуковая карта — сложное устройство. Она имеет *свой внутренний регистр статуса*. 
*   **Бит GPU:** Звуковая карта — сложное устройство. Она имеет *свой внутренний регистр статуса*. 
*   **Бит DMA:** Системый DMA контроллер — сложное устройство. Она имеет *свой внутренний регистр статуса*. 
*   **STORAGE/COM** FDC и UART имеют свои командные/статусные регистры. Central PIC лишь сигнализирует об их активности.


**Регистр маски (IRQ Mask Register) - Read/Write (порт: `0xXX+1`)**
Позволяет программно запрещать обработку отдельных прерываний. Бит `1` - прерывание *разрешено*.

| Бит | Назначение     |
|:----|:---------------|
| 7   | MASK_EXT_SLOT  |
| 6   | MASK_BUS_CRASH |
| 5   | MASK_SUPER_BTN |
| 4   | LEGACY         |
| 3   | AUDIO          |
| 2   | GPU            |
| 1   | DMA            |
| 0   | STORAGE/COM    |

**Регистр подтверждения (IRQ Acknowledge) - Write Only (порт: `0xXX+2`)**
Запись `1` в соответствующий бит сбрасывает флаг в регистре статуса. Запись `0` не оказывает эффекта.

### Спецификация: Механизмы Включения/Выключения Режима Супервизора

**Назначение:** Аппаратное переключение контекста выполнения для изоляции кода ОС/BIOS от пользовательского кода.

| **Механизм Активации**                      | **Тип**         | **Назначение**                                                                                                                          | **Механизм Деактивации**                                  |
|:--------------------------------------------|:----------------|:----------------------------------------------------------------------------------------------------------------------------------------|:----------------------------------------------------------|
| **1. Аппаратное прерывание (INT)**          | **Аппаратный**  | **Основной.** Обработка периферии, крашей, кнопки. Аппаратура выставляет `INT`, в цикл подтверждения выдаёт `0xFF`, ловит `M1 @ 0038h`. | **Команда `RETI`.** Детектор шины ловит `ED 4D`.          |
| **2. Программное прерывание (RST n)**       | **Программный** | **Системные вызовы (SVC).** Пользовательская программа запрашивает услугу ОС (например, через `RST 8`). Ловушка на `M1 @ 0008h`.        | **Команда `RET`.** Детектор шины не требуется.            |
| **3. Не маскируемое прерывание (NMI)**      | **Аппаратный**  | **Аварийный.** Обработка кнопки "Supervisor". Наивысший приоритет. Не блокируется `DI`. Переход по адресу `0066h`.                      | **Команда `RETN`.** Детектор шины ловит `ED 45`.          |
| **4. Запись в порт управления**             | **Программный** | **Принудительный.** Используется кодом супервизора для ручного управления режимом (например, для инициализации или отладки).            | **Запись в порт управления.**                             |
| **5. Ошибка доступа (BUS_CRASH, EXT_SLOT)** | **Аппаратный**  | **Защитный.** Немедленная изоляция сбойного/злонамеренного кода. Аппаратура генерирует `INT` или `NMI` при нарушении.                   | **Через меню супервизора.** По решению ОС (сброс задачи). |

### Краткий итог по работе механизма (для INT)

1.  **Событие:** Устройство поднимает свой `IRQ`. Контроллер устанавливает бит в Status Register.
2.  **Запрос:** Если прерывание не замаскировано, контроллер выставляет `INT` процессору.
3.  **Активность процессора:** Z80 завершает инструкцию, делает `INT Ack` (активные `M1` и `IORQ`). Контроллер в ответ выдаёт на шину данных `0xFF` (`RST 38h`).
4.  **Сохранение состояния:** Z80 сохраняет адрес возврата в стек (в пользовательском режиме памяти).
5.  **Активация супервизора:** Z80 начинает выборку по адресу `0038h`. Аппаратура, отследив `M1 @ 0038h`, переключает память в режим супервизора (ПЗУ BIOS).
6.  **Обработка:** Код в ПЗУ читает Status Register, определяет источник, обрабатывает его.
7.  **Выход:** Код обработчика завершается командой `RETI`.
8.  **Деактивация супервизора:** Аппаратный детектор ловит `ED 4D` на шине и переключает память обратно в пользовательский режим.
9.  **Возврат:** Z80 продолжает выполнение с места прерывания.
