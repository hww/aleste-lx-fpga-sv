# **Amstrad CPC, Aleste 520EX и проект Aleste LX: Анализ I/O и архитектура памяти**

## **1. Введение**

Документ описывает эволюцию управления памятью и вводом-выводом от Amstrad CPC 6128 к Aleste 520EX и предлагает архитектуру для перспективной платформы Aleste LX. Основное внимание уделено решению проблем конфликта адресов и созданию масштабируемой, совместимой системы.

## **2. Amstrad CPC 6128: I/O Space**

Оригинальная платформа использует частичное декодирование адресов, что приводит к потенциальным конфликтам устройств.

**Таблица: Декодирование портов ввода-вывода CPC**

| Аппаратное устройство    | Чтение/Запись | Маска адреса (A15-A0)                          | Примечания                                                                 |
| :----------------------- | :------------ | :--------------------------------------------- | :------------------------------------------------------------------------- |
| Gate Array               | Только запись | `0 1 - - - - - - - - - - - - - -`              |                                                                            |
| PAL (конфигурация RAM)   | Только запись | `0 * - - - - - - - - - - - - - -`              | *A14=1 для CRTC 0/1/2; для совместимости всегда устанавливать в 1.         |
| CRTC                     | Чтение/запись | `- 0 - - - - - - r1 r0 - - - - - -`            | r1, r0: биты выбора регистра.                                              |
| Выбор верхнего ПЗУ       | Только запись | `- - 0 - - - - - - - - - - - - -`              |                                                                            |
| Порт принтера            | Только запись | `- - - 0 - - - - - - - - - - - -`              |                                                                            |
| 8255 PPI                 | Чтение/запись | `- - - - 0 - - - r1 r0 - - - - - -`            | r1, r0: биты выбора регистра.                                              |
| Периферийные расширения  | Чтение/запись | `- - - - - 0 - - x x x x x x x x`              | x: биты, специфичные для устройства.                                       |

## **3. Aleste 520EX: Наследие и конфликты**

Architecture Aleste 520EX является надстройкой над CPC, что приводит к конфликтам адресов.

**Таблица: Порты Aleste 520EX (кратко)**

| Порт    | Статус       | Устройство / Назначение                                    | Конфликт с CPC                |
| :------ | :----------- | :--------------------------------------------------------- | :---------------------------- |
| `0x7C00`| **Сохранить**| Маппер памяти, страница 0                                  | Нет                           |
| `0x7D00`| **Сохранить**| Маппер памяти, страница 1                                  | Нет                           |
| `0x7E00`| **Сохранить**| Маппер памяти, страница 2                                  | Нет                           |
| `0x7F00`| **Сохранить**| Маппер памяти, страница 3 / Gate Array                     | Нет (совмещен с Gate Array)   |
| `0xEEXX`| **Изменить** | 8251 USART (данные)                                        | `0xEFXX` (Порт принтера)      |
| `0xEFXX`| **Изменить** | 8251 USART (управление/статус)                             | `0xEFXX` (Порт принтера)      |
| `0xFABF`| **Изменить** | EXTPORT (регистр управления видео/маппером)                | Нет (новый порт)              |

**Проблема:** Порт принтера CPC (`0xEFXX`) и порт USART Aleste (`0xEE/EFXX`) используют overlapping адресное пространство. Аппаратно разделить их невозможно.

## **4. Aleste LX: Архитектурное предложение**

### **4.1. Режимы работы**

Для решения проблемы конфликтов предлагается два аппаратных режима:
*   **Режим совместимости (Legacy Mode):** Полная эмуляция CPC. Всё новое железо (USART, новый маппер) отключено. Обращения к `0xEFxx` идут на виртуальный принтер.
*   **Нативный режим (Native Mode):** Режим современной ОС. Включено всё новое железо. Обращения к конфликтующим портам CPC траппятся и обрабатываются гипервизором.

### **4.2. Физическое адресное пространство (24 бита)**

В основе — 24-битная шина Wishbone. Пространство разделено на 4 слота по 4 МБ.

| Физический адрес (Hex) | Размер  | Назначение                                                                 |
| :--------------------- | :------ | :------------------------------------------------------------------------- |
| `0x000000` - `0x3FFFFF` | 4 МБ    | **SLOT 0**: Оперативная память, пользовательские программы.                |
| `0x400000` - `0x7FFFFF` | 4 МБ    | **SLOT 1**: Дополнительная RAM или расширения.                             |
| `0x800000` - `0xBFFFFF` | 4 МБ    | **SLOT 2**: Резерв или специальная память (e.g., видеобуфер).              |
| `0xC00000` - `0xFDFFFF` | ~4 МБ   | **SLOT 3**: Пространство гипервизора/ОС.                                   |
| `0xFE0000` - `0xFEFFFF` | 64 КБ   | **Блок I/O #1: Amstrad Compatibility**. Зеркало портов CPC.                |
| `0xFF0000` - `0xFFFFFF` | 64 КБ   | **Блок I/O #2: Aleste LX Native**. Регистры нового железа.                 |

**Ключевой принцип:** Блоки I/O зеркаруются в конце каждого слота. Адрес `0xFF1234` всегда указывает на один и тот же регистр, независимо от активного слота.

### **4.3. Управление памятью (MMU) и слоты**

MMU преобразует 16-битный адрес Z80 в 24-битный физический. Состояние маппера — часть контекста задачи.

**Управление маппером осуществляется через порты ввода-вывода в диапазоне `0xDCXX - 0xDFXX`:**

| Порт I/O  | Назначение                                                                                               |
| :-------- | :------------------------------------------------------------------------------------------------------- |
| `0xDCXX`  | **Bank Register for Page 0 (0000-3FFF) of CURRENT SLOT**                                                 |
| `0xDDXX`  | **Bank Register for Page 1 (4000-7FFF) of CURRENT SLOT**                                                 |
| `0xDEXX`  | **Bank Register for Page 2 (8000-BFFF) of CURRENT SLOT**                                                 |
| `0xDFXX`  | **Bank Register for Page 3 (C000-FFFF) of CURRENT SLOT** / **Upper ROM Bank Number** (совместимость с CPC) |
| `0xDBXX`  | **Slot Select Register**. Записываемый байт (0-3) выбирает активный слот, чьи банковые регистры видны на `DC-DF`. |

**Принцип работы:**
1.  Гипервизор записывает номер слота (0-3) в `0xDBXX`.
2.  Все последующие операции по чтению/записи в порты `0xDCXX` - `0xDFXX` работают с банковыми регистрами *выбранного* слота.
3.  Когда CPU выполняет доступ к памяти, MMU использует банковые регистры *активного на данный момент слота* для трансляции адреса.

**Пример:** Гипервизор хочет настроить маппинг для задачи в Слоте 1.
```asm
LD A, 1
OUT (0xDB00), A    ; Выбираем Слот 1 для настройки
LD A, 5
OUT (0xDE00), A    ; Устанавливаем банк 5 для Страницы 2 (8000-BFFF) в Слоте 1
```
Теперь, когда задача в Слоте 1 будет выполняться, обращение к `0x8000` пойдет в банк 5.

### **4.4. Memory-Mapped I/O (MMIO)**

Для современного управления железом весь верхний сегмент памяти Z80 (`0xC000 - 0xFFFF`) отводится под MMIO. Обращения сюда перенаправляются в физический **Блок I/O #2 (`0xFF0000-0xFFFFFF`)**.

**Таблица: Карта MMIO (CPU адресация)**

| Адрес CPU (Z80) | Адрес в Phys. I/O | Устройство / Регистр                                         | Назначение                                                                 |
| :-------------- | :---------------- | :----------------------------------------------------------- | :------------------------------------------------------------------------- |
| `0xC000`        | `0xFFC000`        | **MMU: SLOT_SELECT**                                         | Выбор активного слота для выполнения. (Запись только гипервизором)         |
| `0xC001`        | `0xFFC001`        | **MMU: BANK_0**                                              | Банк для страницы 0 активного слота.                                       |
| `0xC002`        | `0xFFC002`        | **MMU: BANK_1**                                              | Банк для страницы 1 активного слота.                                       |
| `0xC003`        | `0xFFC003`        | **MMU: BANK_2**                                              | Банк для страницы 2 активного слота.                                       |
| `0xC004`        | `0xFFC004`        | **MMU: BANK_3**                                              | Банк для страницы 3 активного слота.                                       |
| `0xC010`        | `0xFFC010`        | **SYSTEM: GLOBAL_CTRL**                                      | Бит 0: Режим (0=Legacy, 1=Native). Бит 1: Защита записи для пользовательских слотов. |
| `0xC100`        | `0xFFC100`        | **VIDEO: CONTROL**                                           | Регистр управления расширенными видеоатрибутами.                          |
| `0xC200`        | `0xFFC200`        | **SOUND: CH0_FREQ_L**                                        | Младший байт частоты канала 0 (SoundMagic 2.0).                           |
| `0xC300`        | `0xFFC300`        | **SDCARD: DATA**                                             | Чтение/запись данных SD-карты.                                            |
| `0xC400`        | `0xFFC400`        | **NET: STATUS**                                              | Регистр статуса сетевого контроллера.                                     |
| `0xCC00`        | `0xFFCC00`        | **LEGACY EX: USART_DATA**                                    | Данные USART (совместимость с 520EX).                                     |
| `0xD000`        | `0xFFD000`        | **LEGACY CPC: MIRROR_ZONE**                                  | Начало зеркала портов CPC. `0xD000 + (PORT_HI_BYTE << 4)`.                |

*Примечание: Это основа. Точные адреса и набор регистров каждого устройства должны быть детализированы в спецификациях на сами устройства.*

## **5. Итоги и что требует проработки**

Предложенная архитектура решает ключевую проблему конфликтов через два режима работы и provides мощный, масштабируемый фундамент через слоты и MMIO.

**Что требует дальнейшей проработки:**
1.  **Точная эмуляция таймингов:** Реализация цикл-точного эмулятора конфликтующих портов в гипервизоре для Legacy Mode.
2.  **Механизм траппинга:** Детальная проработка аппаратного прерывания CPU при обращении к траппнутым портам в Native Mode и последующей обработки их гипервизором.
3.  **Драйверы:** Разработка драйверов новой периферии (SD, сеть), работающих через MMIO.
4.  **Системные вызовы:** Определение API гипервизора для безопасного доступа к ресурсам из пользовательских задач.
5.  **Детализация MMU:** Разработка точной схемы трансляции адресов, включая обработку исключений и защиту памяти.

Этот документ задает базис и направления для дальнейшего проектирования.
