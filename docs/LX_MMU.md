# MMU Aleste LX

Использует слотовый регистр и маппер подобный тому который используется в MSX платформе. Но есть и некоторые отличия которые позволяют эти два механизма нетолько интегрировать в CPC но и развить их до более продвинутых и по своему привлекательных устройства. В частности сдесь используется 16 байтовый слотовый регистр и дополнительный слотовый регистр. Таким образом существует два слотовых регистра один для поьзователя user а другой для супервизора suprevisor.

## Отсновные режимы процессора

Предназначены для изоляции приложений, а также для высокопроизводительного вызова методов ядра.

- `user mode` в котром действует один из двух MMU один из них legacy (для совместимости с CPC) а другой native (для нового ПО);
- `supervisor mode` в котором действует исключительно native MMU;

Сразу после сброса система запускается в режиме `supervisor mode` а слотовый регистр супервизора после сброса FF
 
## IO Space Краткое введние

Для совместимотси с legacy устройствами поодержиавется Legacy режим, а для нового ПО нативный Native режим. В 24 битном адресном простренсве роазсположены 4 слота. Оследний слот SL3 в последней странице памяти имеет 64 KB область MMIO разбитую на две части MMIO_HI и MMIO_LO.

- MMIO_HI предназначена для Legacy режима и проецирует A[15:0] процессора напрямую;
- MMIO_LO предназначена для нативного режима и проецирует A[7:0] в обоих режимах (Legacy, Native) по разному;

Режимы переключаются битом в LX_MMU менеджере памяти Aleste LX

### Режим Legacy

Работает стандартный MMU от CPC Пространсво I/O подчиняется законам мира CPC и имеет два новых регистра:

2. `MMIO Page Register` (`D300`)-- хранит номер 256 байтной страницы области MMIO_LOW
3. `MMIO Data Window` (`D0XX`) -- производит чтение или запист в обласи MMIO по формуле ```MMIO_LOW + { PAGE[7:0], A[6:0] }```

Таким образом CPC имеет возможность доступатся к MMIO_LOW а значит ипользовать все современные устройства.

### Режим Native

Пространсво I/O подчиняется новым законам. Перефилийные устройства расположены в адресах 00-FF. При этом:

1. В старших адресах C0-FF расположен MMU и резервные области, а в младших 192 байтах `MMIO Data Window`
2. `MMIO Page Register` (`D3` ) -- хранит номер 256 байтной страницы области MMIO_LOW
3. `MMIO Data Window` (`00-BF`) -- производит чтение или запист в обласи MMIO по формуле ```MMIO_LOW + { PAGE[7:0], A[6:0] }```

Таким образом Z80 имеет возможность доступатся к MMIO_LOW а значит ипользовать все современные и Legacy устройства.

### Проецирование в слоты LX

Расширение LX использует слоты подобные слотам MSX, при этом CPC RAM проецируется в Slot 0, а CPC ROM в слот 1.
Гегистр Upper ROM Select определяет страницу памяти отображаемую в адресах с C000 в Slot 1.
Таким образом MMU СPC отвечает на вопрос какой слот и какая его страница включена по адресу XXXX.

## Mative MMU регистры

### GLOBAL_CTRL Регистр

Предназначен для управления основными режимами MMU которых несколько. Самым выжным является supervisor_mode он фактически переключает систему в совершенно особый режим MMU. 

- `native_mode` нативный режим исполнения нового ПО
- `supervisor_mode` режим супервизора. Который включается и отключается не только программно но и автоматически аппаратным устройством;
- `supervisor_hook` включает аппаратную схему слежения за адресом 0000 и 0038 при выборки комманды из которых немедленно включается supervisor_mode. А выключается после выборки reti. Альтернативно, он выключается пои выбоке комманды  0000 и 0038;


| Бит | Название        | Назнчение           |
|-----|-----------------|---------------------|
| 0   | native_mode     | 1-Нативный режим    |
| 1   | supervisor_mode | 1-Режим супервизора |
| 1   | supervisor_hook | 1-Hook активный     |
| 2-6 | reserved        | Резерв              |

Это позволяет выполнить три сценария выхода.

- Выход записью в регистр мгновенно переключит на user mode, что может переключить либо в native либо в legacy в зависимости от native_mode. Что приведет к переключению банков и сдледующая команда будет выбираться от туда;
- Выход RETI используется для для возврата из прерывания которое целиком принадлежало супервизору;
- Доступ M1 к 0038 пердназначен для передачи управления обработчику прерываний CPC. Для этого используется команда JUMP 0038


## Slot Select

Их два, один действует в режиме супервизора а другой в пользовательском режиме. Но оба не доступны пользовательскому окружению. Доступ к ним только через системные вызовы.

В пользовательском legacy режиме не действует ни один. Слоты выбираются `Gate Array Register 2`.

- Подключение ROM активирует слот 1 (SL1)
- Отключение ROM активирует SL0

В нативном режиме деуствует пользовательский слотовый регистр. В итоге карты слотов распределены так:

- `Slot 0` CPC RAM
- `Slot 1` CPC ROM
- `Slot 2` Aleste user space
- `Slot 3` Aleste supervisor space

## Mapper

Cлотовый решистры имеет 4 копии. И активной становится та страница чей слот выбран. Например если в Page 0 выбран Slot3 то регистр Bank 0 Register действует как только для Slot3;

| Внутренний регистр маппера | Имя       | Назначение     |
|:--------------------------:|-----------|----------------|
|            0-3             | MapperSL0 | маппер слота 0 |
|            4-7             | MapperSL1 | маппер слота 1 |
|            8-11            | MapperSL2 | маппер слота 2 |
|           12-15            | MapperSL3 | маппер слота 3 |

Таким образом можно получить ситуацию когда в памяти процессора будут разные слоты, но единый маппер который управляет страницами внутри слотов.

**Пример:**
```asm
; Записать значение 5 в банковый регистр страницы 2 для слота 1
LD A, 4
LD (0x00DB), A   ; PAGE 1 SLOT = 1
LD A, 5
LD (0x00DD), A   ; BANK_1_SEL = 5
; Теперь обращение CPU к 0x4000-7FFF будет идти в банк 5 слота 1
```
