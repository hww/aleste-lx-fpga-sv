Отлично. Мы имеем два документа: вчерашний (полная архитектура памяти и I/O) и сегодняшний (спецификация контроллера прерываний и механизмов супервизора). Задача — объединить их в единую, логичную, непротиворечивую спецификацию, избегая коллизий адресации и следуя принципам KISS и иерархии.

### Объединённая Спецификация: Архитектура Памяти, Ввода-Вывода и Прерываний Aleste LX

---

### 1. Философия Архитектуры: Два Мира

Система функционирует в двух фундаментально разных режимах, управляемых глобальным регистром или "магическим" портом.

*   **Режим Совместимости (Legacy):** Полная, неизменная эмуляция Amstrad CPC + ключевые порты Aleste 520EX, не конфликтующие с CPC (например, маппер памяти по `7C-7Fxx`). Все "зарезервированные" порты CPC работают нативно. Порты Aleste, вызывающие конфликты (USART на `EFxx`), в этом режиме отключены. Предназначен для запуска старого ПО.
*   **Защищённый/Нативный Режим (Native):** В этом режиме:
    *   Аппаратные декодеры для конфликтующих портов CPC (SIO/DART, Timer, Printer на `EFxx`) отключены.
    *   Активны нативные устройства Aleste (USART, EXTPORT, новый PIC).
    *   Включены механизмы защиты памяти и ввода-вывода.
    *   Все обращения к legacy-портам (`FADC`, `EFxx` и т.д.) перехватываются и обрабатываются гипервизором/BIOS для эмуляции старого поведения на новом железе.

### 2. Управление Памятью: Слотинг и MMU (MSX-стиль)

Управление осуществляется через набор регистров, расположенных в едином, логически выделенном пространстве. Эти регистры доступны через **три различных адресных пространства** для максимальной гибкости и совместимости.

**Адресация регистров управления:**

| Регистр              | Назначение                                                                                    | CPC I/O  | 8-Bit Classic | MMIO Page (Native) |
|:---------------------|:----------------------------------------------------------------------------------------------|:---------|:--------------|:-------------------|
| **SLOT_SEL**         | **Выбор активного слота (0-3).** Чей банк виден в `BANK_0..3`.                                | `0xDBXX` | `0xDB`        | `0xC010`           |
| **BANK_0**           | **Банк для страницы 0 (0000-3FFF) активного слота.**                                          | `0xDCXX` | `0xDC`        | `0xC000`           |
| **BANK_1**           | **Банк для страницы 1 (4000-7FFF) активного слота.**                                          | `0xDDXX` | `0xDD`        | `0xC001`           |
| **BANK_2**           | **Банк для страницы 2 (8000-BFFF) активного слота.**                                          | `0xDEXХ` | `0xDE`        | `0xC002`           |
| **BANK_3 / ROM_SEL** | **Банк для страницы 3 (C000-FFFF) активного слота / Выбор верхнего ROM (CPC-совместимость).** | `0xDFXX` | `0xDF`        | `0xC003`           |
| **SYS_CTRL**         | **Глобальное управление.** Bit 0: Режим (0=Legacy, 1=Native). Bit 1: Защита записи.           | `-`      | `0xD7`        | `0xC011`           |
| **MMIO_PAGE**        | **Выбор страницы MMIO для отображения в окно 8-bit space (см. ниже).**                        | `-`      | `0xD3`        | `0xC012`           |

**Как это работает:** Программа переключает слот через `SLOT_SEL`, затем настраивает его страницы через `BANK_0..3`. В Защищённом режиме гипервизор может перехватывать эти записи и виртуализировать маппинг для каждой задачи. Обращения к `BANK_3` также управляют банком ПЗУ в режиме совместимости.

### 3. Memory-Mapped I/O (MMIO) для Защищённого Режима

**Вид из CPU:** 16КБ окно в адресном пространстве Z80 (`0xC000 - 0xFFFF`) является зеркалом физического MMIO-пространства системы. Конкретная 256-байтная "страница" этого пространства, видимая через 8-битные порты, задаётся регистром `MMIO_PAGE`.

**Вид из Wishbone:** Физическое адресное пространство — 24 бита (`0x000000` - `0xFFFFFF`). Блок `0xFF0000-0xFFFFFF` зарезервирован под MMIO и **зеркалируется для каждого слота**. Это обеспечивает единообразие доступа.

**Таблица MMIO (CPU Addresses: `0xC000 - 0xFFFF`):**

| Начало   | Конец    | Длина | Назначение                                                                       |
|:---------|:---------|:------|:---------------------------------------------------------------------------------|
| `0xC000` | `0xC0FF` | 256B  | **Системные регистры.** MMU, слотинг, общее управление. Ядро новой системы.      |
| `0xC100` | `0xC1FF` | 256B  | **Контроллер Прерываний (PIC).** Статус, маска, подтверждение.                   |
| `0xC200` | `0xC2FF` | 256B  | **Звуковой контроллер (SoundMagic 2).**                                          |
| `0xC300` | `0xC3FF` | 256B  | **Графический ускоритель.** Блиттер, спрайты.                                    |
| `0xC400` | `0xC4FF` | 256B  | **DMA-контроллер.**                                                              |
| `0xC500` | `0xC5FF` | 256B  | **Сетевой контроллер.**                                                          |
| `0xC600` | `0xC6FF` | 256B  | **SD Card Host Controller.**                                                     |
| `0xC700` | `0xC7FF` | 256B  | **Часы реального времени (RTC).**                                                |
| `0xC800` | `0xC8FF` | 256B  | **Отладочные и сервисные регистры.**                                             |
| `0xC900` | `0xCBFF` | 768B  | **Резерв.**                                                                      |
| `0xCC00` | `0xCFFF` | 1KB   | **Зеркало портов Aleste 520EX.** USART, EXTPORT.                                 |
| `0xD000` | `0xFFFF` | 12KB  | **Окно для доступа к другим страницам MMIO.** Управляется регистром `MMIO_PAGE`. |

**Доступ через 8-битное пространство:** Запись номера страницы (N) в регистр `MMIO_PAGE` (порт `0xD3`) отображает MMIO-страницу `0xC000 + N*256` на диапазон 8-битных портов `0xD0-0xDF`. Например, при `MMIO_PAGE=0x10`, чтение порта `0xD1` вернёт значение по MMIO-адресу `0xC100 + 0x01 = 0xC101` (бит маски прерываний).

### 4. Спецификация: Центральный Контроллер Прерываний (Master PIC)

**Назначение:** Первичная диспетчеризация. Фиксация запросов от основных групп устройств, генерация `INT` для CPU. Регистры контроллера находятся в MMIO по адресам `0xC100-0xC102`.

**Регистр статуса (IRQ Status Register) - Read Only**
Биты устанавливаются аппаратно по событию и сбрасываются записью `1` в соответствующий бит регистра ACK.

| Бит | Название      | Описание (Группа устройств)                                                               |
|:----|:--------------|:------------------------------------------------------------------------------------------|
| 7   | **EXT_SLOT**  | **Ошибка внешнего слота.** Таймаут или нарушение прав доступа.                            |
| 6   | **BUS_CRASH** | **Краш шины.** Попытка записи в ROM или чтения из несуществующей области.                 |
| 5   | **SUPER_BTN** | **Кнопка "Supervisor".** Аварийный вызов.                                                 |
| 4   | **LEGACY**    | **Группа legacy-устройств.** Общий сигнал от старой периферии (таймер, VDP, старый UART). |
| 3   | **AUDIO**     | **Группа аудио.** Звуковой контроллер (таймер, DMA, ошибка).                              |
| 2   | **GPU**       | **Графический контроллер.** VBlank, HBlank, завершение рендера.                           |
| 1   | **DMA_COM**   | **Группа коммуникаций.** Системный DMA, высокоскоростной последовательный порт.           |
| 0   | **STORAGE**   | **Группа контроллеров хранения.** FDC (флоппи), IDE/SD-контроллер.                        |

**Регистр маски (IRQ Mask Register) - Read/Write**
Бит `1` - прерывание *разрешено*.

| Бит | Назначение     |
|:----|:---------------|
| 7   | MASK_EXT_SLOT  |
| 6   | MASK_BUS_CRASH |
| 5   | MASK_SUPER_BTN |
| 4   | MASK_LEGACY    |
| 3   | MASK_AUDIO     |
| 2   | MASK_GPU       |
| 1   | MASK_DMA_COM   |
| 0   | MASK_STORAGE   |

**Регистр подтверждения (IRQ Acknowledge) - Write Only**
Запись `1` в бит сбрасывает соответствующий флаг в статусном регистре.

**Адресация регистров PIC:**

| Регистр        | MMIO (Native) | 8-Bit Classic | Примечание                                           |
|:---------------|:--------------|:--------------|:-----------------------------------------------------|
| **IRQ_STATUS** | `0xC100`      | `0xD0`        | Доступен для чтения через порт, заданный `MMIO_PAGE` |
| **IRQ_MASK**   | `0xC101`      | `0xD1`        |                                                      |
| **IRQ_ACK**    | `0xC102`      | `0xD2`        |                                                      |

### 5. Механизмы Активации Режима Супервизора

**Назначение:** Аппаратное переключение контекста выполнения для изоляции кода ОС/BIOS от пользовательского кода.

| **Механизм**                        | **Тип**         | **Назначение**                                      | **Выход**            |
|:------------------------------------|:----------------|:----------------------------------------------------|:---------------------|
| **Аппаратное прерывание (INT)**     | **Аппаратный**  | **Основной.** Обработка периферии.                  | **`RETI` (`ED 4D`)** |
| **Программное прерывание (RST n)**  | **Программный** | **Системные вызовы (SVC).** Запрос услуги ОС.       | **`RET`**            |
| **Не маскируемое прерывание (NMI)** | **Аппаратный**  | **Аварийный.** Обработка кнопки "Supervisor".       | **`RETN` (`ED 45`)** |
| **Запись в порт управления**        | **Программный** | **Принудительный.** Используется кодом супервизора. | **Запись в порт.**   |
| **Ошибка доступа (BUS_CRASH)**      | **Аппаратный**  | **Защитный.** Немедленная изоляция сбойного кода.   | **Через меню ОС.**   |

**Алгоритм для INT:**
1.  Устройство -> PIC -> `INT` -> CPU.
2.  CPU -> `INT Ack` -> PIC выдаёт `0xFF` (`RST 38h`).
3.  CPU сохраняет PC, прыгает на `0x0038`.
4.  Аппаратура, детектируя `M1 @ 0038h`, включает режим супервизора (ПЗУ BIOS).
5.  ISR в ПЗУ читает `IRQ_STATUS`, определяет источник, обрабатывает.
6.  `RETI` -> Детектор шины ловит `ED 4D` -> выход из режима супервизора.

### 6. Трансляция Legacy I/O в MMIO

Для обеспечения совместимости обращения к классическим портам CPC в Защищённом режиме трансформируются в обращения к MMIO по простому правилу: `MMIO_ADDRESS = 0xC000 + (ORIGINAL_PORT & 0xFF00)`. Низкие байты портов, участвующие в декодировании, используются для формирования смещения внутри страницы.

**Примеры трансляции:**

| Оригинальный порт | Устройство         | MMIO Адрес (Aleste LX)     | Принцип назначения                                  |
| :---------------- | :----------------- | :------------------------- | :-------------------------------------------------- |
| `0xBCXX`          | **CRTC Index**     | `0xCBC00 + (XX & 0x03)`    | `0xC000 + 0xBC00` + учёт битов декодирования        |
| `0xBDXX`          | **CRTC Data**      | `0xCBD00 + (XX & 0x03)`    | ...                                                 |
| `0xDFXX`          | **ROM Select**     | `0xCDF00`                  | `0xC000 + 0xDF00` (низкие биты игнорируются)        |
| `0xF4XX`          | **PPI Port A**     | `0xCF400 + (XX & 0x03)`    | `0xC000 + 0xF400` + учёт битов декодирования        |
| `0xFB7E`          | **FDC Status**     | `0xCFB0E`                  | `0xC000 + 0xFB00 + 0x0E`. Ручное назначение.       |
| `0xFB7F`          | **FDC Data**       | `0xCFB0F`                  | `0xC000 + 0xFB00 + 0x0F`. Ручное назначение.       |
| `0xFADC`          | **SIO Ch.A Data**  | `0xCFAD0`                  | `0xC000 + 0xFA00 + 0xD0`. Ручное назначение.       |

Этот подход обеспечивает интуитивно понятное соответствие между старыми портами и новыми MMIO-адресами, минимизируя коллизии.
