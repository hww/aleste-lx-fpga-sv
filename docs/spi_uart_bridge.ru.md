## Обзор

Протокол обеспечивает унифицированный доступ к системе через UART (на начальном этапе) и SPI (в будущем). Один атомарный пакет представляет собой одну полную операцию взаимодействия между хост-системой и FPGA. Протокол разделяет доступ к основной памяти и управляющим регистрам для большей гибкости.

## Формат команды (8 бит)

```
[7]   - Резервный бит (0=базовые команды, 1=расширенные команды)
[6:4] - Тип операции  
[3:0] - Параметры/размер данных
```

## Базовые команды 

Все базовые команды действуют при условии когда резервный бит равен 0. Это основной набор операций для повседневной работы с системой.

### Основные типы операций:
- `000` - **Чтение памяти** (через Wishbone)
- `001` - **Запись памяти** (через Wishbone)  
- `010` - **Чтение регистров** (управление FPGA)
- `011` - **Запись регистров** (управление FPGA)
- `100` - **Ивенты** (мгновенные действия с параметрами)
- `101` - **Глобальный статус** (запрос состояния системы)
- `110` - *Резерв*
- `111` - *Резерв*

### Кодирование размера данных 

При операциях с данными биты [3:0] сообщают о размере передаваемого пакета. Это позволяет эффективно работать с различными объемами информации.

```
`0000` - 1 байт
`0001` - 2 байта  
`0010` - 4 байта
`0011` - 8 байт
`0100` - 16 байт
`0101` - 32 байта
`0110` - 64 байта
`0111` - 128 байт
`1000-1111` - *Резерв*
```

## Спецификация команд

Ниже перечислены основные типы команд которые обеспечивают раздельный доступ к памяти и регистрам управления, а также отправку событий и запрос системного статуса.

### Чтение памяти (`0_000_xxxx`)

Операция чтения данных из основной системной памяти через Wishbone шину. Используется для доступа к видеопамяти, RAM и другим memory-mapped устройствам.

```
Отправка: [CMD] [ADDR 24-bit]
Получение: [DATA N-bytes]
```

**Пример:** `0_000_0010` - чтение 4 байт из памяти по адресу 0x001000

### Запись памяти (`0_001_xxxx`)  

Операция записи данных в основную системную память через Wishbone шину. Обеспечивает прямой доступ ко всем memory-mapped ресурсам системы.

```
Отправка: [CMD] [ADDR 24-bit] [DATA N-bytes]
Получение: [ACK 8-bit] (0x00 = успех)
```

**Пример:** `0_001_0001` - запись 2 байт в видеопамять по адресу 0xC000

### Чтение регистров (`0_010_xxxx`)

Операция чтения значений из управляющих регистров FPGA. Регистры используются для конфигурации системы, управления периферией и получения статуса различных модулей.

```
Отправка: [CMD] [REG_ADDR 8-bit]
Получение: [REG_VALUE 8-bit]
```

**Пример:** `0_010_0000` - чтение регистра статуса видеоконтроллера (адрес 0x10)

### Запись регистров (`0_011_xxxx`)

Операция записи значений в управляющие регистры FPGA. Позволяет настраивать систему, запускать тесты и управлять аппаратными модулями.

```
Отправка: [CMD] [REG_ADDR 8-bit] [REG_VALUE 8-bit]
Получение: [ACK 8-bit] (0x00 = успех)
```

**Пример:** `0_011_0000` - запись значения 0x55 в регистр конфигурации (адрес 0x01)

### Ивенты (`0_100_xxxx`)

Операция отправки мгновенных событий с параметрами. Ивенты используются для запуска однократных действий, которые не требуют сохранения состояния в регистрах.

```
Отправка: [CMD] [EVENT_ID 8-bit] [PARAM 8-bit]
Получение: [STATUS 8-bit]
```

**Примеры ивентов:**
- `0_100_0000` - Сброс процессора (параметр: тип сброса)
- `0_100_0001` - Генерация прерывания (параметр: номер IRQ)  
- `0_100_0010` - Генерация NMI прерывания  
- `0_100_0100` - Запуск теста памяти (параметр: тип теста)

### Глобальный статус (`0_101_xxxx`)

Операция запроса общего состояния системы. Возвращает комбинированный байт статуса, содержащий ключевые флаги состояния различных подсистем.

```
Отправка: [CMD]
Получение: [STATUS 8-bit]
```

**Биты статуса:**
- `[0]` - CPU halted (процессор остановлен)
- `[1]` - System reset active (система в сбросе)  
- `[2]` - HDMI VSYNC (импульс кадровой синхронизации)
- `[3]` - SD card inserted (карта памяти установлена)
- `[4]` - Reset button pressed (нажата кнопка сброса)
- `[5]` - PLL locked (тактовые генераторы стабильны)
- `[6]` - SDRAM calibrated (память откалибрована)
- `[7]` - FPGA overload (перегрев или перегрузка)

## Расширенные команды (резервный бит = 1)

Команды `1_xxxxxxx` зарезервированы для будущих версий протокола. Полная свобода переопределения семантики для расширения функциональности без нарушения обратной совместимости.

## UART Implementation Notes

### Границы пакетов:
- **Таймаут**: 3.5 символа без данных = конец пакета
- **Фиксированная длина**: определяется по команде

### Скорости:
- **Базовая**: 9600 бод (совместимость с демо)
- **Рабочая**: 115200 бод  
- **Максимальная**: 1 Мбод (для SPI в будущем)

## SPI Migration Path

### Естественный переход:
- **CS сигнал** определяет границы атомарных операций
- **Тот же протокол** - меняется только физический уровень
- **DMA поддержка** для эффективной передачи данных

### 4-wire SPI преимущества:
- **Двойная скорость** с dual/quad mode
- **Потоковые операции** без пауз между байтами
- **Аппаратная поддержка** в микроконтроллерах

## Примеры использования

```python
# Чтение 4 байт из видеопамяти
send([0x02, 0x00, 0x10, 0x00])  # CMD=0x02, ADDR=0x001000
receive([0x12, 0x34, 0x56, 0x78])  # Данные

# Запись регистра конфигурации
send([0x30, 0x01, 0x55])  # CMD=0x30, REG=0x01, VALUE=0x55
receive([0x00])  # Подтверждение успеха

# Запрос глобального статуса
send([0x50])  # CMD=0x50
receive([0x25])  # Статус: PLL locked + CPU halted

# Отправка ивента сброса
send([0x40, 0x01, 0xFF])  # CMD=0x40, EVENT=0x01, PARAM=0xFF
receive([0x00])  # Статус выполнения
```
